# 雑談における焦点操作と語用動機の分析方針（暫定）

## 目的と位置づけ

非タスク指向の雑談を対象に、情報共有の展開を「焦点がどう動いたか」と「その動きにどのような語用的な狙いが読み取れるか」に分けて記述する。

`focus_pragmatics` の操作・動機の分類を仮の分析枠として使い、実際の対話スクリプトで説明できる範囲と、判断に迷う境界を確かめる。現時点では対象スクリプトは未提供であり、実例による検証前の方針とする。

元のプロンプトは次の発話の意図候補を Decision に渡すためのものだが、この分析では、すでに起きた発話と会話の展開を記述する。返答生成やタスク完了の達成度評価は目的にしない。

## 分析の単位と文脈

- 発話を前後の流れの中で読む。直前の一発話だけでなく、それまでの話題や参照関係から焦点を再構成する。
- 一発話に複数の操作がある場合は、必要な箇所だけ区切って記述する。具体的な分割基準は試行で調整する。
- 操作を選ぶ前に、焦点の前後を短く記述する。例：`活動 → 頻度`。
- 後続の反応は、その働きが相手にどう受け取られたかを見る材料とする。話者の動機を確定する証拠とはしない。

## 焦点操作

| 操作 | 暫定的な判断基準 |
| --- | --- |
| `paraphrase` | 同じ焦点を別表現で受ける。軽い整理、言い換え、確認を含む。 |
| `switch` | 現在焦点と関連する近い概念へ注目を移す。活動から回数、現在から過去、事実から評価への移行など。 |
| `add` | 現在の焦点に属性、数量、評価、例、具体化、補足、対比などの情報を足す。値更新も含む。 |
| `topic_shift` | 現在の焦点系列を閉じ、別話題へ移る。 |

`switch` と `add` は重なりやすいため、「注目先が移ったか」「同じ注目先の情報が増えたか」を区別の目安にする。ただし、これは確定した判定規則ではない。実例で判断が割れる場合は、候補と迷いの理由を残す。

相づちや笑いなど、4操作に収めにくい発話は無理に分類せず保留する。分類の追加・変更は、試行で得られた事例を踏まえて検討する。

## 語用動機

| 動機 | 読み取る狙い |
| --- | --- |
| `affiliation` | 距離感、共感、顔、関係性を整える。 |
| `self_interest` | リスク、境界、立場を守る。 |
| `play` | 軽さ、冗談、誇張、からかい、意外性を作る。 |
| `epistemic` | 理解合わせ、認識修正、整理、精度向上を図る。 |
| `meta` | 会話進行、順序制御、切替、段取りを整える。 |

動機は話者の内心を確定するラベルではなく、根拠付きの解釈として扱う。言い回しや直前のやり取りを根拠に候補を付け、複数の解釈がある場合は併記し、判断材料が不足する場合は保留する。操作と動機は別々に判断する。

終助詞や推量表現などは解釈の手掛かりにするが、特定の表現と操作・動機を一対一に対応させない。

## 会話全体の展開

発話ごとの分類に加えて、操作の連なりを読む。例えば、言い換えを重ねて理解を合わせる流れや、属性を足してから別の経験へ移る流れを記述する。

生成用プロンプトにある「switch と add を自然に混ぜる」「paraphrase の連続では停滞を疑う」「add の連続では情報過密を疑う」は、実際の会話の良否を決める基準にはしない。繰り返しがその場で何をしているかを文脈から確かめる。

## 記録形式と進め方

分析記録は、元の生成用プロンプトの1行出力形式に限定せず、次の表を基本とする。

| 発話 | 焦点の前→後 | 操作 | 動機候補 | 判断の根拠・迷い |
| --- | --- | --- | --- | --- |

1. 対象スクリプトから連続した短い一場面を選ぶ。
2. 焦点の前後を記述し、操作と動機候補を根拠とともに付ける。
3. 操作の連なりを読み、場面全体の展開を記述する。
4. 分類の重なり、保留した発話、文脈不足の箇所を確認する。
5. 試行結果を踏まえて分類の境界と記録方法を調整してから、対象を広げる。

初回の成果物は、一場面の分析表、展開の記述、判断に迷った点の一覧とする。網羅的な分類体系や定量評価の設計は、この段階では確定しない。
