# 雑談における焦点操作と構図の分析方針（暫定）

## 目的と分析枠の位置づけ

非タスク指向の雑談を対象に、情報共有の展開を「焦点がどう動いたか」と「誰がどのように構図を変えようと働き掛け、相手がどう応じたか」の二つの観点に分けて記述する
ここでいう雑談は、特定の課題の達成ではなく、話すこと自体を目的とする対話を指す
分析するのは記録された発話と発話間の関係であり、次の返答の生成や課題達成の評価は行わない

本方針は、焦点操作4種類と語用動機からなる依頼者提示の分析枠を出発点とした
試行の結果、語用動機は構図への働き掛けと応じ方に置き換えた（「構図」の節を参照）
分類の定義はすべて本文書に記載し、外部のプロンプトや会話履歴を前提にしない

| 区分 | 位置づけ |
| --- | --- |
| 依頼者提示の分析枠 | 4操作により、雑談の焦点の動きを捉える |
| 原典の知見 | 発話単位、やりとり、修辞関係、モダリティ、構図と立場、再現に関する研究を参照する |
| 本方針での分析上の提案 | 発話の参照先、当該発話の焦点、操作、構図への働き掛けと応じ方、共有コンテキストの更新、判定上の不確実性を記録し、短い一場面ずつ試行する |

4操作と構図の候補は、参考文献で提案・検証された分類そのものではない
操作と構図への働き掛けを別々に記録するのも分析上の選択であり、両者が統計的に独立していると主張するものではない
分類の妥当性と再現性は、試行を重ねて確かめる

## 原典から参照すること

### 発話の位置づけと分類基準

荒木ほか（1999）は課題遂行対話を対象に、当初は別々だった発語内行為・ムード・やりとりの観点を統合し、やりとりの中での発話の位置づけと、決定木によるタグ選択を採用している
評価では、タグ名や文末表現に引きずられた判定の不一致も報告されている
このことから、分類名だけで判断せず、基準と文脈を確認する必要性が読み取れる
ただし、この研究の対話構成や一致率を、そのまま本方針の雑談分析に当てはめることはできない
参照箇所：[第2〜4章、252–259頁](https://www.jstage.jst.go.jp/article/jjsai/14/2/14_251/_pdf/-char/ja)

### 局所的なやりとりと発話内容の関係

徳久・寺嶌（2007）は、まず発話間のやりとりを認定し、そのうえで役割を分類している
一つの発話が応答と働きかけの双方を担う場合も扱い、間接応答や問い返しについて、修辞関係とそれが現れる場面を分析している
問い返しについては、修辞関係の分析に先立って、先行発話との表層的な関係も分類している
ただし、雑談の分析対象は一方の話者から他方へ情報を伝える部分に限られ、問い返しの修辞関係の分析も情報付加型に絞られている
参照箇所：[第2〜4章、426–434頁](https://www.jstage.jst.go.jp/article/tjsai/22/4/22_4_425/_pdf)

本方針では、この研究から、先行発話とのつながりを参照先として記録する必要性を読み取る
同論文の Addition と本方針の `add`、Reformulation と `paraphrase` は、対象と判定基準が異なるため同一視しない
修辞関係は詳述・因果など発話内容どうしの関係であり、焦点操作や構図とは区別する

### 表現の意味と語用論的効果

井上「モダリティ」は、命題内容に対する判断と、聞き手への発話・伝達態度を区別し、表現の意味と、文脈の中で生じる語用論的効果とを関連づけて記述している
終助詞の分析では、文法的性質、使用できる文脈、イントネーション、方言差も検討している
参照箇所：[第1・2・4節、133–148頁](https://www2.ninjal.ac.jp/takoni/DGG/09_modarityi.pdf)

本方針でも、敬体への切り替えや終助詞などの表現を構図の判定の手掛かりにするが、表現の種類を構図に直接対応させはしない
原典が扱う表現の意味と、そこから文脈の中で生じる効果とを区別して扱う

### 構図と立場

Goffman は、話し手が聞き手や自分の発話に対して取る立ち位置（footing）が会話の中で変わることを論じ、声を出す者・言葉を組み立てる者・その立場に責任を負う者を区別した（production format）
また、ある活動を遊びや芝居など別のものとして行い直すこと（keying）を論じている
本方針では Goffman の原文を参照できておらず、footing と参与の枠組みについては M. H. Goodwin（2000）の整理を介して参照する
参照箇所：[Goodwin（2000）177–178頁](https://anthro.ucla.edu/wp-content/uploads/2025/10/1999_Participation.pdf)

本方針では、この議論から、話者が誰として誰に向けて話すかと、活動を何として行うかを、発話の内容とは別に捉える必要性を読み取る
ただし本方針の「構図」は、Goffman の footing と keying をまとめて、試行で観察した場のありように合わせて定めたものであり、Goffman の概念そのものではない

### 再現

Thompson & Suzuki（2014）は、日本語と英語の会話で、話者が過去の出来事を演じて見せる再現（reenactment）を分析している
再現には、元の出来事の場と、いま再現している場の二つの層が重なり、話者は聞き手に当時の誰かの役を振ることがある
日本語の例では、「〜とか言って」「〜って言われてさ」などの引用表現が再現の範囲を示している
参照箇所：[1–3頁、例は7・12・17頁](https://escholarship.org/content/qt2351k7cs/qt2351k7cs_noSplash_f21c4065a985713f8c99b7248aa50dec.pdf)

本方針では、この研究から、再現を語りとは別の構図として扱い、引用表現を再現の境目の手掛かりにする
同研究の分析は視線と身振りに基づいており、文字スクリプトだけでは同じ判断はできない

## 分析の単位と文脈

以下は、原典を踏まえて本方針で暫定的に定める運用である
分析は発話順に進め、各発話の判定には当該発話とそれまでの文脈だけを用いる
後続発話をもとに、それより前の発話の焦点・操作・構図への働き掛けを判定し直すことはしない

会話は、共有信念・相互信念・共有基盤と呼ばれる共有されたコンテキストを前提とし、進展に伴ってそれを更新する
発話に基づかない事前のコンテキストは常に存在する
お題、その場にあるもの、共有された記憶などは発話番号を付けて扱わず、分析範囲の前提として記録する
お題の読み上げや、事前のコンテキストから話題を振る発話は、通常の発話として扱う

- 元の発話本文、話者、発話順を保持し、各発話に識別用の番号を付ける
- 話者が一回に発言するまとまりであるターンと、分析のためにターン内を区切った発話単位とを区別する
- 一つのターンに回答と補足など区別できる部分があれば区切り、分割後の各部分に元の発話番号の枝番を付ける
- 一つの部分が複数の働きを持つだけであれば、タグを一つに絞るための分割はしない
- どの先行発話を受けているかを番号で記録し、直前以外の発話や複数の発話を受ける場合もその番号を残す
- 場面の冒頭など先行文脈が不足する箇所では、判断できない項目を保留して「判定上の不確実性」に記す

当該発話が先行発話に対して回答、補足、問い返しなどのどの関係にあるかを、当該発話までの文脈から判断する
この関係は参照先と操作の判定に用いるものであり、発話ごとに説明文として記録はしない
原典のタグ体系一式を新たな必須分類として導入するものではない

原典のタグ付けには、音声を利用した判断が含まれる
文字スクリプトだけを扱う場合は、抑揚、間、笑い方などを推測で補って解釈せず、それらを要する判断は保留する
音声やト書きが利用できる場合も、当該発話時点までに得られる情報に限って用いる

## 焦点操作

当該発話の焦点は、その発話が注目を向けている対象や側面を指す
参加者全員の注目がそこへ移ったことを意味するものではない
先行発話の焦点は参照先の行で把握し、当該発話の行には重ねて記録しない
操作は、参照先の焦点と当該発話の焦点を同程度の細かさで比較して判断する
例えば、先行発話の焦点を広く「旅行」、当該発話の焦点を細かく「旅行の回数」と捉えただけで、焦点が移動したと判定しない
先行発話ですでに回数が問題になっていなかったかを確認する

| 操作 | 依頼者提示の定義 |
| --- | --- |
| `paraphrase` | 同じ焦点を別表現で受ける（軽い整理、言い換え、確認を含む） |
| `switch` | 現在の焦点と関連する近い概念へ注目を移す（活動から回数、現在から過去、事実から評価への移行など） |
| `add` | 属性、数量、評価、例、具体化、補足、対比など新情報を足す（値更新も含む） |
| `topic_shift` | 現在の焦点系列（関連する焦点をたどる一連の流れ）を閉じ、別話題へ移る |

判定には、次の暫定基準を用いる

- `paraphrase` は、確認や疑問の形だけで決めず、同じ焦点を受け直しているかを見る
- `switch` は何から何へ注目を移しているか、`add` は何に対してどの情報が加わったかを確認する
- 評価や具体化などは `switch` と `add` の両方に関わりうるため、両者の間に機械的な優先順位は設けない
- `topic_shift` は新しい単語の出現だけで決めず、それまでの焦点の連なりと新しい話題との関係を見る
- 相づちや笑いも、形式だけを理由に分類対象から外さず、焦点への働きを記述できるかを確認する

同じ箇所に複数の操作が認められることと、どの操作か判定できないことを区別する
判定できない場合は、分類に当てはまらないのか、複数の解釈が残るのか、情報が不足するのかを「判定上の不確実性」に記す

## 構図

構図は、どのような活動の中で、誰がどの立場で、誰に向けて話しているかという場のありようを指す
話者の立場（本人として話すか、当時の自分や役として話すか、誰に向けて話すか）は構図に付随するものとして扱い、別には記録しない
構図は入れ子になりうる（例えば、語り合いの中に当時の場面の再現が埋め込まれる）

| 構図 | 場のありよう | 話者の立場 |
| --- | --- | --- |
| 語り合い | 参加者が本人として、互いに向けて話す | 本人 |
| 再現 | 過去の場面を演じて見せる。当時の発言のほか、当時の心の中の声も含む | 当時の自分、当時の相手 |
| 冗談 | 本気でない枠で、からかい、誇張、見立てなどをする | 本人（冗談を言う側、受ける側） |
| 芝居 | 現実とは異なる役柄を演じ合う（恋人役など） | 役 |
| 配信 | 配信者として視聴者に向けて話す。視聴者から寄せられたお題に応じることを含む | 配信者 |
| 独白 | 相手に向けず、自分に向けて話す（自問、想起、納得） | 本人（自分に向けて） |

これらは試行1・2の範囲から得た暫定の候補であり、他の場面で必要になれば追加する

### 構図への働き掛けと応じ方

各発話の構図そのものではなく、構図を変えようとする働き掛けと、それへの相手の応じ方を記録する
当該発話の時点の構図は、記録した働き掛けと応じ方を発話順にたどって把握する

「構図への働き掛け」には、当該発話がそれまでの構図とは異なる構図へ移ろうとする場合に、移る先を「再現へ」「冗談へ」「芝居へ」「配信へ」「独白へ」「語り合いへ」のように記録する
相手が応じたかどうかにかかわらず、当該発話の言い回しとそれまでの文脈から判定する
構図を変えない発話は空欄にする

「構図への応じ方」には、相手の働き掛けを最初に受ける発話について、次のどちらかを記録する
それ以外の発話は空欄にする

| 値 | 応じ方 |
| --- | --- |
| 参加 | 相手が持ちかけた構図に入って応じる（再現の中で当時の自分を演じる、役を引き受ける、冗談に乗るなど） |
| 不参加 | 持ちかけられた構図に入らずに応じる（再現を外から評価する、本気で受け答えするなど） |

独白への働き掛けには、相手が加わることがないため、応じ方は記録しない
構図は、明示的な働き掛けがないまま途切れることがあり、その場合は終わりを記録しない

構図への働き掛けは、依頼者提示の分析枠にあった語用動機（推定動機）を置き換えたものである
試行1・2では、推定動機の値が同意などの受け入れの発話で一つに偏り、文脈どおりの展開では発話ごとの違いを区別しなかった
一方で、文脈から予想しにくい展開（人物評価、見立て、小芝居への移行、再現、視聴者に向けた総括など）は、多くが話す立場と活動の枠を変える働き掛けとして説明できた
各発話の構図を記録する形も試したが、大半の発話が語り合いのままで、展開として意味を持つのは構図を変えようとする働き掛けと、それに相手が乗るかどうかだった
そのため、話者の狙いを推定する代わりに、構図への働き掛けと応じ方を記録する

判定には、次の暫定基準を用いる

- 働き掛けと応じ方は、当該発話時点までの言い回しと連鎖から判断し、話者の狙いの推定には頼らない
- 手掛かりには、引用・再現を示す表現（「みたいな」「って」「とか言って」）、敬体への切り替え、役柄を示す語、笑いなどを用いる。ただし表現の形だけで決めない
- 構図への働き掛けがあった発話は、文脈から予想しにくい展開として、焦点の推移の記述で取り上げる
- 冗談・芝居・再現の構図の中の発話にも、焦点操作と共有コンテキストの更新は通常どおり判定する
- 芝居の構図の中での同意・了解は、役どうしの受け入れとして扱い、現実の出来事についての共通認識とは区別する
- 後続の発話で相手が応じたことを根拠に、当該発話の働き掛けを判定し直さない
- 判定できない場合は保留し、「判定上の不確実性」にその内容を記す

「維持」「展開」などの談話効果は、独立した必須タグとしては設けない

## 共有コンテキストの更新

会話の進展に伴う共有コンテキストの更新のうち、当該発話が先行発話の内容を共有コンテキストとして受け入れたかどうかを記録する
焦点の動きを表す操作や、構図への働き掛けと応じ方とは別に判定する
受け入れた内容は「参照する先行発話」と「当該発話の焦点」からたどれるため、この欄には受け入れ方だけを記録する

| 値 | 受け入れ方 |
| --- | --- |
| 同意 | 先行発話の内容を事実として認め、共通認識とする |
| 了解 | 先行発話の内容を受け取ったことを示すが、事実として認めてはいない |

当該発話が受け入れを示さない場合は空欄にする
同意か了解かは、話者がその内容を自分で確かめられる立場にあるか（共に経験した出来事か、相手だけが知る事情か）と、当該発話の言い回しから判断する
相づちも、形式だけで同意または了解と決めず、何を受け入れているかを確認する

## 記録形式

発話番号・話者・本文を保持したスクリプトに、次の分析表を対応させる
原則として一行に一つの分析単位を記録し、分割した場合は `12a`・`12b` のように元の発話番号に枝番を付ける
番号から分析対象の本文をたどれるため、対象範囲の列は設けない

| 発話番号 | 参照する先行発話 | 当該発話の焦点 | 操作 | 構図への働き掛け | 構図への応じ方 | 共有コンテキストの更新 | 判定上の不確実性 |
| --- | --- | --- | --- | --- | --- | --- | --- |

「参照する先行発話」には、当該発話が応答・言及している先行発話の番号を記録する
先行発話ではなく分析範囲の前提として記録した事前のコンテキストを受ける場合は「前提」と記録する
「当該発話の焦点」には、その発話が注目を向けている対象や側面を記録する
「操作」「構図への働き掛け」「構図への応じ方」「共有コンテキストの更新」には、それぞれの分類から判定した結果を記録する
「判定上の不確実性」には、判定が定まらない項目とその不確実性だけを記し、該当しなければ空欄にする
各列には一つの項目だけを記録し、一つのセルに矢印や小見出しを使って複数の項目をまとめない
判断根拠を行ごとに文章で記す欄や、後続の反応を記す欄は設けない

## 試行と見直し

1. 対象スクリプトから連続した短い一場面を選び、範囲、利用できる音声・場面情報、前提とする事前のコンテキストを記録する
2. 発話順に、当該発話までの情報で参照先、当該発話の焦点、操作、構図への働き掛けと応じ方、共有コンテキストの更新を判定し、判定上の不確実性があれば記す
3. 記録済みの参照先・焦点・操作・構図への働き掛けと応じ方を発話順にたどり、焦点の推移と構図の移り変わりを記述する
4. 判断が分かれる箇所を、単位の切り方、参照先、焦点の細かさ、操作、構図への働き掛けと応じ方、共有コンテキストの更新、情報不足の観点に分けて見直す
5. 判定基準を変えた場合は理由を残し、その基準が関わる発話を、それぞれの発話時点までの情報で判定し直す

操作の種類や連続回数だけで会話の良否を判定しない
言い換えや情報追加が続く場合も、それぞれの発話時点の文脈に沿って判定する
操作を均等に出現させることや、質問・話題移行を増やすことを分析の目標にはしない

初回の成果物は、一場面の分析表、焦点の推移の記述、判定上の不確実性を踏まえた基準の修正案とする
同じ基準で説明できた箇所と説明できなかった箇所を確認してから、対象を広げる
一人による試行だけでは再現性を確認できたとはみなさない
定量評価や複数の分析者による一致率の検証は、別途設計する
